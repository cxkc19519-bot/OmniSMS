# 项目实施计划

状态：已确认，执行中

## 当前进度（2026-08-17）

- 阶段 0：Android、Gmail、VPS 资源和入口方案已验证；Cloudflare Universal SSL 仍在自动签发。
- 阶段 1：Android 与 Go 正式工程、安全配置、HMAC 签名、防重放、幂等、配置样例和自动化测试已在本地完成；待 VPS 上验证真实 HTTPS 空链路。
- 阶段 2：消息接收、SQLite 队列、Gmail SMTP、退避重试、成功后清空正文、24小时清理和健康检查代码已完成；待使用用户自行写入 VPS 的凭据进行真实投递验收。
- 阶段 3：短信广播、双卡元数据、加密本地队列、WorkManager、前台服务和 Direct Boot 核心代码已完成；待正式 APK 在 OPPO 上安装及端到端验证。
- 阶段 4 至阶段 6：未完成。当前安卓界面是用于安全配置和联调的功能骨架，不是最终界面。

## 阶段 0：技术可行性验证

目标：用最小实验消除高风险不确定性，不开发完整产品。

任务：

- 确认 OPPO 的实际 Android API、短信权限和侧载流程。
- 验证单卡/双卡短信广播、多段短信合并及 SIM 信息可用性。
- 验证 ColorOS 自启动、锁屏、清理后台和省电模式下的行为。
- 确认 VPS 操作系统、架构、可用端口、域名和现有代理占用情况。
- 验证 Gmail 合规授权和测试邮件投递。
- 验证同账号自发自收是否触发 iPhone Gmail 推送。

退出条件：形成验证记录；所有阻塞项已有经用户确认的解决办法。

## 阶段 1：项目骨架与安全基础

任务：

- 初始化 Android 与 Go 工程。
- 建立格式化、静态检查、单元测试和秘密扫描。
- 定义 API schema、错误码和数据库迁移。
- 实现设备配对、请求签名、HTTPS 开发环境和配置校验。
- 添加不含真实凭据的配置示例。

退出条件：空消息链路能经过认证；错误日志无敏感信息。

## 阶段 2：服务端最小闭环

任务：

- 实现消息接收、输入校验和幂等存储。
- 实现邮件模板与 Gmail 投递。
- 实现邮件投递重试和状态机。
- 实现24小时数据清理。
- 实现健康检查和结构化日志。

退出条件：测试客户端提交虚构短信后只收到一封格式正确的邮件；重试和清理测试通过。

## 阶段 3：安卓短信接收与可靠队列

任务：

- 实现权限流程和短信接收器。
- 实现多段短信合并与双卡元数据采集。
- 实现本地加密队列。
- 实现 WorkManager 上传、退避重试和幂等键。
- 实现重启恢复与24小时清理。

退出条件：模拟器和 OPPO 真机可稳定采集并补发虚构测试短信。

## 阶段 4：App 界面与用户引导

任务：

- 实现首次设置向导、首页、发送记录和设置页。
- 实现测试邮件、暂停/恢复、手动重试和清除记录。
- 编写 ColorOS 权限、自启动和省电设置引导。
- 完成敏感信息遮挡、错误文案和无障碍检查。

退出条件：非技术用户可依据界面独立完成安装和首次配置。

## 阶段 5：端到端验证与加固

任务：

- 完成 `07-testing-and-acceptance.md` 全部关键场景。
- 测试断网、VPS 重启、邮件失败、重复请求、手机重启和时间偏差。
- 检查 APK、日志、数据库和备份中的敏感数据。
- 进行24小时以上真实待机测试。
- 修复阻塞和高优先级问题。

退出条件：所有发布门槛通过，剩余限制由用户接受。

## 阶段 6：部署与交付

任务：

- 按 `08-deployment-and-operations.md` 部署 VPS。
- 配置 HTTPS、systemd、清理任务、日志轮转和监控。
- 生成签名 APK，并安全保存签名材料。
- 在 OPPO 安装并完成 Gmail/iPhone 通知验证。
- 交付安装、恢复、升级和卸载说明。

退出条件：真实双卡短信端到端成功，用户能够自行确认系统状态。

## 建议执行顺序

阶段必须按 0 → 1 → 2 → 3 → 4 → 5 → 6 推进。服务端先形成可测试闭环，再接入真实短信，便于定位问题并减少真机调试成本。

## 变更管理

- 每个阶段开始前确认范围和输入条件。
- 阶段中发现需求冲突时暂停相关实现，先更新需求并取得确认。
- 涉及新增费用、第二邮箱、域名购买或 VPS 重大改动时单独确认。
