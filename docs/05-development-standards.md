# 开发规范

## 1. 仓库建议结构

```text
OmniSMS/
├─ android/                 # 安卓 App
├─ server/                  # VPS 服务端
├─ deploy/                  # systemd、Caddy 和部署示例
├─ docs/                    # 项目标准文档
├─ scripts/                 # 本地检查与发布辅助脚本
├─ Codex.md                 # 工作入口
└─ README.md                # 面向使用者的项目说明（编码阶段创建）
```

目录在开始编码时按需要创建，不预先放置无用途的空文件。

## 2. 通用代码原则

- 代码优先清晰、可测试和易恢复，不做无需求支撑的抽象。
- 业务时间使用 UTC；展示层明确转换时区。
- 错误分类至少区分：可重试、需用户处理、永久数据错误。
- 所有网络写入操作必须具备幂等语义。
- 外部输入必须做长度、格式和枚举校验。
- 注释解释原因和限制，不重复代码表面行为。

## 3. Kotlin/Android 标准

- 使用官方 Kotlin 格式规范，格式检查由构建任务执行。
- UI、业务逻辑、数据存储和系统接收器职责分离。
- `BroadcastReceiver` 只做快速解析与落盘，不执行长网络请求。
- Room schema 变化必须提供迁移和迁移测试。
- 协程必须使用结构化并发，不使用无生命周期约束的全局协程。
- UI 状态采用不可变模型；错误展示使用用户可理解的映射。
- 权限相关代码必须覆盖允许、拒绝、永久拒绝和系统撤销场景。
- 发布构建关闭调试日志，并配置代码混淆后功能验证。

## 4. Go/服务端标准

- 使用 `gofmt`，静态检查和测试必须进入 CI。
- HTTP handler 只负责校验和编排；邮件、数据库、认证分别封装。
- 所有 I/O 使用超时和可取消 context。
- 数据库迁移版本化，启动时不得悄悄执行破坏性变更。
- 日志使用结构化字段并经过敏感信息过滤。
- 健康检查区分进程存活和依赖就绪。
- 优雅停机应停止接收新请求，并在限定时间内完成正在处理的工作。

## 5. 配置标准

- 开发、测试和生产配置分离。
- 仓库只提交 `.env.example` 等无秘密示例。
- 必需配置在启动时校验，缺失时快速失败并给出字段名。
- 密钥不得通过命令行参数传递，以免进入进程列表或 shell 历史。
- 默认配置必须安全：HTTPS 必需、调试关闭、正文日志关闭。

## 6. Git 与变更规范

- 每个提交聚焦一个可说明的目的。
- 提交前运行相关格式化、静态检查和测试。
- 不提交构建产物、IDE 私有配置、签名文件、数据库或真实配置。
- 需求或行为变化必须同步更新文档和测试。
- 不重写或删除他人未确认的改动。

建议提交消息：

```text
feat(android): add durable SMS outbox
fix(server): make email delivery idempotent
docs: clarify Gmail notification validation
test(android): cover multipart SMS assembly
```

## 7. 测试标准

- 单元测试覆盖解析、状态机、签名、幂等、重试和清理逻辑。
- 集成测试使用虚构短信和测试邮箱，不使用生产凭据。
- 安卓关键流程必须在 OPPO 真机测试。
- 服务端发布前运行数据库迁移、重启恢复和重复请求测试。
- 修复缺陷时尽量先补充能复现问题的测试。

## 8. 完成定义

一项开发任务只有在以下条件都满足时才完成：

- 行为满足需求和验收条件。
- 自动化测试通过。
- 相关真机或部署检查完成，或明确记录尚未完成原因。
- 没有新增明文秘密和敏感日志。
- 受影响文档已更新。
- 已知限制和回退方式已记录。
