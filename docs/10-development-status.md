最后更新：2026-08-18

## 1. 当前结论

项目已经完成 VPS 部署、Gmail 实投、24小时待机和 OPPO 正式签名包冒烟测试。Cloudflare 边缘证书及 VPS 源站证书均已生效，公网 HTTPS 健康检查通过。0.3.3 服务端已部署，Android 0.3.4 已完成旧通知基线、持久去重和正式签名发布。正式包已在 OPPO 上重新配对并开启转发；DNS 故障期间进入加密队列的虚构测试消息在解析恢复后自动补发，Gmail 仅收到一封。当前仍需完成备份/恢复、回滚演练及全量验收，因此尚未宣布最终生产验收结束。

## 2. 已实现

### 服务端

- Go 单进程服务，默认只监听 `127.0.0.1:8088`。
- `POST /v1/messages`、存活检查和数据库就绪检查。
- HMAC-SHA256 请求签名、5分钟时间窗口、随机数防重放和设备身份检查。
- `device_id + message_id` 与幂等键去重。
- SQLite WAL 短期队列、Gmail STARTTLS SMTP、指数退避和永久配置错误停止重试。
- 邮件包含发送方、SIM、短信接收时间、实际转发时间、补发标记和完整正文。
- 固定 `Message-ID` 降低 SMTP 成功但确认丢失时产生重复邮件的风险。
- 邮件成功后立即清空 SQLite 正文；服务端记录及未投递正文最长24小时清除。
- systemd 和 Nginx 独立站点样例，不修改现有代理节点。

### 安卓端

- 正式包名 `com.omnisms.app`，最低 Android 12（API 31）。
- 新短信广播、多段合并、可获得的双卡卡槽信息。
- Android Keystore AES-GCM 加密服务器配置、设备密钥、发送方和短信正文。
- SQLite 可靠待发队列；成功后清除本地发送方和正文。
- HTTPS 系统证书校验、与服务端一致的 HMAC 签名、WorkManager 网络约束和指数退避。
- 持续前台服务、隐私安全通知、`LOCKED_BOOT_COMPLETED`/`BOOT_COMPLETED`/解锁恢复；新短信优先由前台服务在短时唤醒锁内直接上传，WorkManager 仅作失败重试兜底。
- 服务恢复时按短信库递增编号补查系统收件箱（最多24小时），用不可逆消息指纹与唯一索引避免广播路径和补查路径重复投递；首次授权不回传既有历史短信。真机验证表明 ColorOS 的短信记录时间可能与系统时间相差数小时，因此不得使用绝对时间作为唯一游标。
- ColorOS 5G消息通知监听：严格只允许 `com.android.mms`；普通 SMS 若已进入标准收件箱或15秒内刚触发标准 SMS 广播，则忽略通知路径；同一通知会话等待2.5秒并选择最长正文，再以会话和消息时间去重；首次授权不处理旧通知，服务重连可恢复24小时内仍存在的系统短信通知。
- 简体中文联调界面：安全连接、短信权限、开启/暂停、队列状态和固定虚构测试消息。
