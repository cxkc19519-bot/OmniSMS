# 安全与隐私规范

## 1. 数据分类

| 数据 | 级别 | 示例 |
|---|---|---|
| 高敏感 | S3 | 完整短信、验证码、设备密钥、Gmail 应用专用密码 |
| 敏感 | S2 | 手机号/发送方、邮箱地址、VPS 地址、消息时间 |
| 内部 | S1 | App 版本、匿名错误码、队列数量 |
| 公开 | S0 | 无真实数据的使用说明 |

S3 数据不得进入源码、Git、崩溃报告、分析平台或普通日志。

## 2. 传输安全

- 所有 App 到 VPS 的通信只允许 HTTPS。
- 不允许忽略 TLS 错误、接受自签名证书或回退到 HTTP。
- 请求必须包含防重放信息并使用设备密钥签名。
- 服务端限制请求体大小、时间偏差和速率。
- 错误响应不得回显短信正文或密钥。

## 3. 凭据管理

- Gmail 普通登录密码永不使用、永不保存。
- Gmail 应用专用密码或 OAuth 凭据只保存在 VPS 的受限环境文件或凭据存储中。
- `.env`、密钥文件和生产配置必须在 `.gitignore` 中。
- 安卓设备密钥由服务端生成或安全配对，并用 Android Keystore 保护。
- App 界面不显示完整密钥，只提供重新配对/轮换能力。
- 所有示例配置使用占位符。

## 4. 本地数据

- 短信必须先可靠落盘再投递，防止进程被系统结束时丢失。
- 本地短信正文使用由 Android Keystore 保护的密钥加密。
- 成功投递后可立即删除正文；状态记录最长保留24小时。
- 用户执行“清除本地记录”前显示影响，清除动作不影响已进入 Gmail 的邮件。
- App 备份默认排除短信数据库和密钥材料。

## 5. 服务端数据

- 服务端仅为投递和重试短期保存短信，最长24小时。
- 数据库文件权限仅服务账号可读写。
- 数据库备份默认不包含短信表；不得因系统备份延长短信保留期。
- 每小时执行过期清理，并记录删除数量，不记录被删内容。
- 邮件发送成功后可以提前清除正文，仅保留非敏感投递状态至24小时。

## 6. 日志规范

允许记录：

- 随机消息 ID 的截断或哈希形式。
- 投递状态、错误码、耗时、重试次数。
- App/服务版本和不含身份信息的系统状态。

禁止记录：

- 短信正文或验证码。
- 完整发送方、邮箱地址、设备密钥或邮件凭据。
- 完整请求体或认证请求头。

## 7. 邮件与通知风险

- 邮件标题默认不包含短信正文或验证码。
- 完整正文进入 Gmail 后由 Gmail 的安全和保留策略管理，不受24小时清理约束。
- 用户应为 Gmail 开启两步验证。
- iPhone 锁屏是否展示邮件正文由用户的通知预览设置决定。
- 测试邮件必须使用固定虚构内容，不得复制最近真实短信。

## 8. 安全验收清单

- 仓库扫描无真实凭据和真实短信。
- HTTPS 证书校验不能被配置关闭。
- 认证失败不能继续无上限重试。
- 同一请求重放不会产生第二封邮件。
- 日志检查无 S3 数据。
- 24小时清理任务有自动测试和部署后验证。
- 服务以非 root 账号运行，配置权限最小化。
