# 部署与运维规范

## 1. 部署前提

- 确认 VPS 操作系统和 CPU 架构。
- 确认现有代理节点占用的端口、反向代理和防火墙规则。
- 准备指向 VPS 的域名及有效 HTTPS 证书方案。
- 准备 Gmail 合规授权凭据和接收地址。
- 确认系统时间同步正常；认证依赖可靠时间。

不得在未检查现有代理服务的情况下修改防火墙、80/443 端口或反向代理配置。

## 2. 推荐部署布局

```text
/opt/omnisms/            # 程序文件，只由部署账号写入
/etc/omnisms/            # 生产配置和秘密，严格权限
/var/lib/omnisms/        # SQLite 数据库
/var/log/omnisms/        # 如不完全使用 journald，则存放受轮转日志
```

实际路径可按 VPS 系统调整，但程序、配置、数据和日志必须分离。

## 3. 服务运行标准

- 使用专用非 root 系统账号运行。
- systemd 设置合理的重启策略、资源限制和文件权限掩码。
- Caddy 或现有反向代理负责 TLS，后端仅监听本机地址。
- 防火墙只开放必要端口。
- 健康检查不得返回配置、邮箱、消息或版本控制秘密。
- 生产环境默认关闭调试模式。

## 4. 数据与备份

- 程序和无秘密配置可备份。
- 生产秘密单独加密备份，并限制访问。
- 默认不备份包含短信正文的 SQLite 数据。
- 若为灾难恢复必须备份数据库，应先实现正文加密、短保留和备份同步过期机制。
- 恢复演练使用测试数据，不使用真实短信。

## 5. 日志和监控

建议监控：

- 服务是否在线。
- 最近一次成功邮件投递时间。
- 待投递数量和最老消息年龄。
- 连续失败次数。
- 数据库和磁盘占用。
- 24小时清理任务是否按时运行。

告警不得包含短信正文、完整发送方、邮箱或密钥。日志设置大小和保留天数限制。

## 6. 发布与回滚

1. 构建并校验版本化二进制文件。
2. 在测试环境运行迁移和集成测试。
3. 备份当前程序及数据库 schema 信息。
4. 部署新版本并执行健康检查。
5. 发送固定虚构内容的测试邮件。
6. 观察错误率和队列状态。
7. 失败时恢复上一版本；数据库迁移必须预先说明是否可逆。

不得通过删除生产数据库来解决升级失败。

## 7. 常见故障处理

### 手机不再转发

- 检查 App 总开关和短信权限。
- 检查 ColorOS 自启动、后台活动和省电限制。
- 检查待发送数量和认证状态。
- 使用测试邮件区分手机监听问题与邮件问题。

### VPS 收不到请求

- 检查域名、TLS、服务状态和现有代理配置。
- 检查系统时间偏差和认证错误码。
- 不通过关闭 TLS 或认证来临时绕过问题。

### Gmail 收不到或不通知

- 检查服务端投递状态和 Gmail 垃圾邮件。
- 检查 Gmail App 的账号同步与 iOS 通知权限。
- 验证自发自收限制；需要改变发件通道时先取得用户确认。

### 队列持续增长

- 暂停新增部署变更。
- 判断是认证、网络、Gmail 限流还是永久格式错误。
- 修复后让队列受控恢复，避免短时间集中重试。

## 8. 卸载与退役

- 安卓端先暂停转发并清除本地数据，再卸载 App。
- VPS 撤销设备密钥和 Gmail 授权。
- 停止服务后删除短信数据库和生产凭据，保留无敏感信息的必要审计记录。
- Gmail 中既有邮件不会随 App 或 VPS 删除，需用户自行处理。

## 9. OmniSMS 首次部署执行顺序

以下步骤必须在证书签发后执行；示例域名、邮箱和密钥均为占位符：

1. 在本地完成 `go test ./...`、`go vet ./...` 和 Linux x86_64 交叉构建。
2. 在 VPS 创建 `omnisms` 系统账号，以及 `/opt/omnisms`、`/etc/omnisms`、`/var/lib/omnisms`，数据目录只允许该账号读写。
3. 上传 `server/build/omnisms-server-linux-amd64` 到 `/opt/omnisms/omnisms-server`，权限设为 `0755`。
4. 复制 `server/.env.example` 为 VPS 上的 `/etc/omnisms/omnisms.env`，填入真实配置并设为 `0600`；真实文件不得回传或进入仓库。
5. 使用 `server/cmd/omnisms-keygen` 生成至少32字节设备密钥，只分别写入 VPS 配置和手机安全配置。
6. 安装 `deploy/omnisms.service`，启动后先从 VPS 本机检查 `/health/live` 与 `/health/ready`。
7. 参考 `deploy/nginx-omnisms.conf.example` 新增独立 `server_name`；先执行 `nginx -t`，成功后才平滑重载。不得覆盖现有 35551 或代理节点配置。
8. 从公网验证 HTTPS 证书和健康检查，确认 HTTP 不被 App 接受。
9. 使用固定虚构测试内容验证 Gmail；不得用真实验证码做首次测试。
10. 安装正式 APK，完成 OPPO 权限、ColorOS 后台设置、断网补发、重启和 Gmail 通知验收。

任何一步失败都应停在当前层排查，不得通过关闭 TLS、认证、数据加密或证书校验绕过。
