# 安卓 App 界面与交互规范

## 1. 设计目标

- 面向不懂技术的个人用户。
- 首页一眼看出“是否正在工作”和“最近一条是否成功”。
- 错误信息说明影响，并给出具体解决按钮。
- 不在无必要的页面展示完整短信或验证码。

## 2. 页面结构

### 2.1 首次设置向导

建议步骤：

1. 用途与隐私说明。
2. 短信权限申请。
3. 连接服务器：扫码或输入配对信息，避免手工输入长密钥。
4. 填写并确认接收 Gmail。
5. ColorOS 自启动、后台活动和省电设置引导。
6. 发送测试邮件。
7. 完成并进入首页。

每一步必须说明“为什么需要”和“不授权会怎样”。用户拒绝权限后应能再次进入系统设置，不循环弹窗。

### 2.2 首页

顶部状态卡：

- 正常：绿色，“短信转发正在运行”。
- 暂停：灰色，“短信转发已暂停”。
- 待处理：橙色，“有 N 条短信等待发送”。
- 故障：红色，“短信无法转发”，附解决入口。

首页操作：

- 开启/暂停总开关。
- 查看最近一次成功时间。
- 查看待发送数量。
- 发送测试邮件。
- 进入“发送记录”和“设置”。

### 2.3 发送记录

- 默认只显示最近24小时。
- 列表显示发送方的脱敏形式、接收时间、状态和是否补发。
- 默认不显示正文；用户主动进入详情后才能查看。
- 失败项提供“重试”按钮和通俗错误说明。
- 提供“清除本地记录”，并说明 Gmail 邮件不会被删除。

### 2.4 设置

- 接收 Gmail 地址。
- 服务器连接状态与重新配对。
- 时区，默认 Asia/Shanghai。
- 权限与 ColorOS 设置检查。
- 数据保留说明。
- App 版本和诊断信息导出；诊断信息不得包含短信正文或密钥。

## 3. 核心文案

| 场景 | 建议文案 |
|---|---|
| 正常运行 | 短信转发正在运行 |
| 无短信权限 | 未获得短信权限，无法监听新短信 |
| 断网 | 当前没有网络，短信将在联网后自动发送 |
| 认证失败 | 手机与服务器的连接已失效，请重新配对 |
| 测试成功 | 测试邮件已发送，请检查 Gmail |
| 测试失败 | 测试失败：{通俗原因} |
| 暂停确认 | 暂停后，新短信不会自动上传，恢复后是否补发取决于短信是否已进入队列 |

## 4. 通知与隐私

- 安卓端可用常驻或状态通知提升后台状态可见性，但是否必需在可行性阶段验证。
- 安卓通知不得显示短信正文或验证码。
- App 最近任务缩略图和锁屏界面应避免暴露短信详情。
- Gmail 邮件标题不包含短信正文；iPhone 通知正文预览由用户自行配置。

## 5. 可用性与无障碍

- 主要按钮触控区域不小于平台建议尺寸。
- 状态不只依靠颜色，还必须配合文字和图标。
- 支持系统字体缩放，关键按钮不被截断。
- 错误消息不得只显示 HTTP 状态码或异常堆栈。
- 高风险操作必须说明影响，但不要用多重弹窗干扰正常使用。
